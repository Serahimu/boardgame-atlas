# Boardgame Atlas 功能與優化規劃

規劃日期：2026-10-18
評估基準：`6aa3477`，依 README、HTML、`app.js`、`styles.css`、資料 JSON 與 Python 資料處理腳本檢視。
狀態：提案清單，尚未實作；各項需求在進入開發前仍需確認資料來源、範圍與驗收細節。

## 1. 產品方向與現況

將網站從桌遊資料目錄，逐步發展為「挑選遊戲、管理規則書、整理收藏與準備逛展」的工具。

現有能力包括兩份清單、出版社目錄、搜尋、多條件篩選、格狀／列表、分頁、遊戲關聯與文件查找。原清單有 120 款主遊戲、170 個項目；Essen 清單有 1,745 款主遊戲、3,666 個項目，並包含 20,719 份文件。資料為來源快照，並非即時查詢。

本規劃完整保留本次評估提出的 **108 個項目**，以 `BA-001` 至 `BA-108` 對應原建議序號。優先級代表建議順序，並不代表已承諾全部開發，也不包含工期估算。

### 已觀察到的技術現況

- `index.html` 約 5.47 MB，160 筆圖片使用 data URI；原清單資料仍內嵌於 HTML，修改 Excel 不會自動更新。
- `data/essen.json` 約 6.52 MB，包含清單和詳情欄位；文件已採 32 份分片、按需載入及頁面內快取，可沿用這個方向。
- 出版社 JSON 在主要初始化流程中等待載入，可改善為桌遊目錄先顯示。
- 搜尋會遍歷所有字串欄位，包括網址及來源註記；每次輸入會重新篩選、排序與重建結果畫面。
- 出版社支援網址路由；單款遊戲詳情和完整篩選狀態尚未進入網址。
- Essen 項目 ID 依資料列順序產生；不同版次可能共用 BGG ID，因此持久識別碼不能只依資料列或 BGG ID。
- 原清單以名稱連結主遊戲與相關項目；Excel 轉換依固定工作表、欄位與起始列配置讀取。

以上屬原始碼和資料檢視結果，尚未以瀏覽器量測效能或逐頁驗證互動。

## 2. 優先級與開發原則

| 優先級 | 定義 |
| --- | --- |
| P1 | 核心使用價值、資料正確性或後續功能的必要基礎 |
| P2 | 提升探索、操作與日常使用體驗 |
| P3 | 新情境延伸、需要額外資料或服務的進階能力 |

- 優先維持可部署至 GitHub Pages 的靜態架構，避免為功能清單直接導入大型框架或後端。
- 個人資料先考慮瀏覽器儲存與匯出備份；大量結構化資料可評估 IndexedDB，帳號同步另立階段。
- 先建立穩定項目識別碼、資料格式與遷移規則，再持久儲存收藏、網址和遊玩紀錄。
- 來源資料、人工修正、個人筆記及 AI 產生內容應能辨識來源，避免把推測呈現為已確認事實。
- 效能工作先記錄載入量、請求、初始化與搜尋耗時，再於相同條件比較成果。
- 現有搜尋、出版社導覽、多對多關聯、文件快取與 GitHub Pages 子路徑相容性應持續保留。

## 7. 外部資料、服務與開發前決策

- **中文名稱、版本差異與擴充需求**：確認來源與維護方式；無法查證的項目保留未知狀態。
- **翻譯 PDF 發布**：先決定網站用途是私人索引、受限存取或公開發布。GitHub Pages 的公開資源不能因介面隱藏就視為私人；本機掃描不得自動將整個翻譯資料夾加入發布產物。
- **圖片與規則文件**：保留來源和權利資訊；離線包只包含允許儲存或發布的內容，外部文件不保證能直接快取。
- **攤位、價格、盒重與匯率**：目前並未完整包含於既有資料，需另行取得、標示日期並定義更新頻率。
- **清單分享**：先評估可分享網址、匯出檔或雲端清單各自的容量與隱私限制。
- **同步和多人協作**：需決定服務供應商、驗證方式、衝突解決、資料刪除及維護成本；密鑰不得放入公開前端。
- **規則問答**：需先完成文件可讀取性、版次對應與頁碼引用；再評估模型服務、成本、檢索及答案品質。
- **推薦與情境標籤**：先使用現有資料及明確規則；「家庭」「聚會」等標籤需定義判斷依據，不能直接當來源事實。

## 8. 驗收與驗證策略

### 共通驗收

- 兩份清單均可搜尋、篩選、排序、分頁與進入出版社及相關項目。
- 共用 BGG ID 的不同版次、重名項目、多對多和巢狀關聯均有代表案例。
- 未提供數值、缺圖、缺文件、失效來源和請求失敗有明確狀態，不填入未確認資料。
- URL 在 GitHub Pages 專案子路徑可用；直接開啟、重整、上一頁／下一頁的行為一致。
- 手機無水平溢出；鍵盤可完成核心流程；對話框／抽屜關閉後焦點能合理返回。
- 個人資料可匯出還原，資料格式版本變更有遷移或明確錯誤說明。

### 效能驗收

- 變更前後以相同瀏覽器、裝置及網路條件記錄 HTML／JSON 傳輸量、請求數、首次可操作時間和搜尋延遲。
- 確認初次載入與重訪快取均有改善；不能只把主檔縮小卻提前下載全部分片。
- 連續搜尋、快速切換遊戲及失敗重試，不得顯示前一款遊戲的文件或過期結果。
- 取得基準後再訂量化門檻，不先宣稱尚未量測的效能成果。

### 檢查範圍

資料建置驗證必要欄位、唯一識別、關聯與資源存在性；前端對核心資料和導覽邏輯加入必要回歸測試。版面調整採桌面／手機視覺檢查，避免為單純靜態文字或低影響樣式堆疊重複測試。

## 9. 開發追蹤方式

後續可依 `BA-xxx` 建立 issue 或細部實作規劃，每張工作項目至少包含：

- 使用情境與實際要改變的行為。
- 對應的 BA 編號、前置依賴及納入／不納入範圍。
- 資料來源、格式遷移與缺值處理。
- 可操作的驗收步驟和需要的回歸案例。
- 完成後的資料版本、相容性與文件更新。

完成狀態應在實際交付與驗收後更新，不以規劃文件已列出作為功能完成依據。
